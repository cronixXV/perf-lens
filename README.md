# PerfLens

**PerfLens** — инструмент для анализа производительности веб-сайтов, который помогает находить причины медленной загрузки и выявлять проблемы, влияющие на пользовательский опыт.

Вместо простого набора метрик PerfLens анализирует загрузку ресурсов, Web Vitals, длительные задачи JavaScript и зависимости между ресурсами, а затем формирует список проблем с приоритетами.

## Возможности

### Анализ производительности

- Анализ веб-сайта в headless Chromium с помощью Playwright.
- Сбор информации о загруженных ресурсах: тип, размер, время загрузки и сетевые характеристики.
- Измерение Core Web Vitals и дополнительных метрик производительности:
  - LCP — Largest Contentful Paint;
  - INP — Interaction to Next Paint;
  - CLS — Cumulative Layout Shift;
  - FCP — First Contentful Paint;
  - TTFB — Time to First Byte.
- Обнаружение длительных задач JavaScript (Long Tasks).
- Анализ JavaScript-ресурсов и их суммарного размера.
- Построение графа зависимостей ресурсов.
- Определение блокирующих рендеринг CSS-ресурсов.

### Поиск проблем

PerfLens автоматически выявляет потенциальные причины низкой производительности:

- Медленная отрисовка основного контента (LCP).
- Слишком большие изображения.
- Избыточный размер JavaScript.
- Длительные задачи, блокирующие основной поток.
- CSS-файлы, блокирующие рендеринг.

Каждая проблема содержит категорию и уровень серьёзности: `critical`, `warning` или `info`.

### История анализов

- Сохранение результатов анализа в SQLite.
- Просмотр истории выполненных анализов.
- Повторное открытие сохранённых результатов.
- Получение истории с backend API.

### Сравнение результатов

- Сравнение двух анализов одного или разных состояний сайта.
- Отображение изменений ключевых метрик.
- Визуализация Before / After.
- Графики для наглядного отслеживания изменений производительности.

## Архитектура

Проект организован как monorepo с разделением на три workspace:

```text
perflens/
├── client/
│   └── src/
│       ├── app/
│       ├── pages/
│       ├── widgets/
│       ├── features/
│       ├── entities/
│       └── shared/
│
├── server/
│   └── src/
│       ├── domain/
│       ├── application/
│       ├── infrastructure/
│       ├── presentation/
│       └── app/
│
├── shared/
│   └── src/
│       └── contracts/
│
├── package.json
└── README.md
```

**Frontend — Feature-Sliced Design**

Клиентская часть разделена на слои `app`, `pages`, `widgets`, `features`, `entities` и `shared`. Для управления серверным состоянием используется TanStack Query, а для навигации — TanStack Router.

**Backend — Clean Architecture**

Серверная часть разделена на независимые слои:

- `domain` — бизнес-модели и правила предметной области.
- `application` — сценарии выполнения анализа.
- `infrastructure` — Playwright, Chromium и SQLite.
- `presentation` — HTTP API и обработка запросов.
- `app` — композиция приложения и внедрение зависимостей.

**Shared contracts**

Общие TypeScript-контракты используются клиентом и сервером для согласованной передачи результатов анализа и ошибок.

## Как работает анализ

1. Пользователь вводит URL сайта.
2. Frontend отправляет запрос на backend.
3. Backend запускает Chromium через Playwright.
4. Playwright открывает страницу и собирает данные через браузерные API и Chrome DevTools Protocol.
5. Собранные данные нормализуются и передаются в систему анализа.
6. Система выявляет проблемы производительности и формирует результат.
7. Результат сохраняется в SQLite и возвращается клиенту.
8. Пользователь может изучить метрики, графики, список проблем и сравнить анализы.

## API

Основные HTTP endpoints:

| Метод | Endpoint            | Назначение                  |
| ----- | ------------------- | --------------------------- |
| POST  | `/analyses`         | Запустить анализ сайта      |
| GET   | `/analyses`         | Получить историю анализов   |
| GET   | `/analyses/:id`     | Получить сохранённый анализ |
| GET   | `/analyses/compare` | Сравнить два анализа        |
| GET   | `/health`           | Проверить состояние сервера |

## Запуск проекта

### Требования

- Node.js 22+
- npm
- Chromium для Playwright

### Установка

```bash
git clone <repository-url>
cd perflens
npm install
npx playwright install chromium
```

### Переменные окружения

Для backend и frontend используются переменные окружения.

Пример для frontend:

```env
VITE_API_URL=http://localhost:3000
```

Пример для backend:

```env
DATABASE_PATH=./data/perf-lens.db
```

Названия и расположение переменных должны соответствовать конфигурации конкретного workspace.

### Запуск в режиме разработки

Из корня проекта:

```bash
npm run dev
```

Frontend и backend запускаются параллельно.

## Основная цель проекта

PerfLens создаётся как инженерный portfolio-проект, демонстрирующий навыки разработки не только интерфейсов, но и полноценной системы с браузерной автоматизацией, сбором и обработкой данных, backend API, хранением результатов и визуализацией аналитики.

Особое внимание уделяется архитектуре, типизации, обработке ошибок, производительности и безопасности.
